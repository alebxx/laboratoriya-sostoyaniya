# Методика: решения и их обоснование

Здесь записаны все методические решения проекта: что сделано, почему и на какой источник это опирается. Числовые параметры живут в `src/config.js`; если меняете параметр там, обновите и этот файл.

## 1. Общие принципы

- **Не медицинский инструмент.** Сайт не ставит диагнозов, не выводит «уровень стресса» из физиологии или теста, не сравнивает значения с нормами и не сравнивает пользователя с другими людьми. Все сравнения делаются только внутри данных одного человека.
- **Связь — не причина.** Все выводы формулируются как совпадения: «в дни, когда…, вы чаще…». Причинные формулировки не используются.
- **Приватность.** Данные хранятся только в браузере пользователя (IndexedDB). Сервера, регистрации, аналитики и внешних запросов нет. Шрифты системные, библиотеки входят в сборку.

## 2. Хранение данных

- **Где:** IndexedDB, база `laboratoriya-sostoyaniya`. localStorage используется только для выбранной темы оформления.
- **Версии:** у базы есть номер версии (`DB_VERSION` в `src/db/db.js`), у файла экспорта — номер формата (`SCHEMA_VERSION` в `src/config.js`). При изменении структуры номер увеличивается, а старые данные переводятся в новый формат функциями-миграциями.
- **Одна запись дневника на день:** ключ записи — дата, поэтому повторное сохранение заменяет запись за этот день (её можно редактировать).
- **Риск потери данных.** Данные браузера пропадают в режиме инкогнито и при очистке данных сайтов. Поэтому:
  - на первом экране есть предупреждение;
  - сайт просит браузер хранить данные постоянно (`navigator.storage.persist()`), но браузер может отказать;
  - раз в 7 дней (если есть данные) появляется напоминание сделать резервную копию, его можно отложить на 1 день.

## 3. Граница суток

Записи и сеансы, сделанные до **4:00**, относятся к предыдущему дню (`DAY_START_HOUR` в `src/config.js`).

**Зачем.** Если человек заполняет дневник или проходит тест в 01:00 ночи, по смыслу это ещё «вчерашний» день: он ещё не спал. Без этой границы поздние записи попадали бы в следующий день, и связь «сон прошлой ночью → состояние сегодня» перепутывалась бы.

Это проектное решение, а не научная норма. Порог можно поменять.

## 4. Экспорт и импорт

- **JSON** — полная копия всех хранилищ с полями `app`, `schemaVersion`, `exportedAt`. Из неё можно всё восстановить.
- **CSV** — отдельная таблица для каждого раздела (дневник, физиология, сеансы теста, попытки теста, PSS-10, гипотезы). Разделитель столбцов — точка с запятой, дробная часть чисел — через запятую («6,5»), в начале файла стоит BOM (знак кодировки), чтобы русская версия Excel правильно открыла файл. Списки внутри ячейки записываются как JSON-текст.
- **Импорт** принимает только JSON этого сайта. Файл проверяется (название приложения, версия формата, известные разделы). Файл от более новой версии сайта не принимается. Импорт **заменяет** текущие данные одной транзакцией: при ошибке данные не меняются.

## 5. Дневник

- **Одна запись на день**, её можно редактировать. День записи считается с учётом границы суток (раздел 3). Можно выбрать и прошедший день, если запись была забыта, но не будущий.
- **Время записи.** Сохраняются время создания (`createdAt`) и время последнего изменения (`updatedAt`).
- **Все поля необязательны.** Не отмеченное поле сохраняется как пустое (`null`), а не как 0: «не ответил» и «ответил 0» — разные вещи. Поэтому у ползунка есть состояние «не отмечено». Пока ползунок не сдвинули, значение не сохраняется, а кнопка «Сбросить» возвращает это состояние. Совсем пустая запись не сохраняется.
- **Шкалы 0–10** для стресса, усталости, качества сна и концентрации — это простые шкалы самооценки, сделанные для этого проекта. Это **не** валидированные опросники, и их значения нельзя сравнивать с чужими. Они нужны только для сравнения дней одного человека между собой. Подписи краёв шкал нейтральные.
- **Сон** — часы от 0 до 16 с шагом 0,5 («прошлой ночью», то есть относится к дню записи).
- **Настроение** — 5 вариантов (1–5).
- **Свои факторы** — пользователь сам создаёт отметки «да/нет» или числа. Фактор нельзя удалить, только скрыть: так не теряются старые отметки и не ломаются гипотезы, которые на него опираются. Для «да/нет» есть третий вариант «не отмечено», чтобы отсутствие отметки не считалось ответом «нет».
- **CSV дневника:** заголовки столбцов на русском, со шкалой в скобках («Стресс (0–10)»). Время указано по местному времени в виде «ГГГГ-ММ-ДД ЧЧ:ММ». Причины записаны через запятую, каждый свой фактор — отдельный столбец «Фактор: название», демо-записи помечены. В JSON-копии названия полей остаются английскими: их читает программа при импорте.

## 6. Мягкая забота

- Если стресс от **9** и выше отмечен **3 дня подряд** (настройка `CARE` в `src/config.js`), после сохранения записи показывается спокойное сообщение. В нём говорится, что сайт не заменяет поддержку, и названо, к кому можно обратиться. Текст вставляет автор (`src/data/messages.js`).
- «Подряд» — значит по календарным дням без пропусков. День без записи или без отметки стресса прерывает серию.
- Сообщение показывается **один раз на серию**. Если высокий стресс продолжается, оно не повторяется. Если серия прервалась, а потом началась новая, сообщение покажется снова.
- Это не оценка состояния и не диагноз: сайт не делает выводов о человеке, а только напоминает о поддержке. Пороги — проектное решение, а не клинический критерий.

## 7. Тест на внимание PVT-B

### 7.1. Что измеряет тест
PVT (Psychomotor Vigilance Test) — тест на простое время реакции: человек как можно быстрее реагирует на сигнал, который появляется в случайные моменты. Он измеряет **бдительность** (устойчивость внимания) и чувствителен к недосыпу (Lim, Dinges, 2010). PVT **не измеряет стресс**, поэтому сайт не делает по нему выводов о стрессе.

PVT-B — укороченный трёхминутный вариант, предложенный и проверенный Basner, Mollicone, Dinges (2011).

### 7.3. Показатели сеанса
- **Медиана времени реакции** — главный показатель. Считается по всем ответам на сигнал, кроме фальстартов; пропуски входят. Медиана устойчива к единичным очень долгим реакциям.
- **Скорость реакции** — среднее значение 1/RT (в 1/с, то есть 1000 / RT в мс). Его часто используют как основной показатель PVT (**TODO: сверить** с Basner et al., 2011, какие показатели там названы наиболее чувствительными). В отличие от медианы, он учитывает и медленные реакции.
- **Пропуски** — число реакций ≥ 355 мс (включая «нет ответа»).
- **Фальстарты** — нажатия до сигнала и реакции < 100 мс.
- **Стимулы** — сколько раз появлялся сигнал. Нажатия до сигнала стимулами не считаются, а реакции < 100 мс — считаются: сигнал был.
- Сырые данные каждой попытки сохраняются: интервал ожидания, момент сигнала и нажатия от начала теста, время реакции, тип попытки, чем нажато.

### 7.4. Измерение времени в браузере и какие задержки остаются
- **Часы.** Используется `performance.now()` — монотонные часы браузера с точностью до долей миллисекунды. Они не зависят от перевода системного времени.
- **Появление сигнала.** Таймер (`setTimeout`) срабатывает примерно через нужный интервал, после чего сигнал рисуется в ближайшем кадре: внутри колбэка `requestAnimationFrame`. Сразу после изменения страницы запоминается момент сигнала. Так момент привязан к кадру отрисовки, а не к произвольному моменту таймера.
- **Момент нажатия.** Берётся `event.timeStamp` — время самого события клавиатуры или касания по тем же часам. Оно точнее, чем время, когда обработчик дошёл до события.
- **Что остаётся неточным:**
  - *Экран.* Между командой «нарисовать» и реальным появлением картинки проходит от долей кадра до 1–2 кадров (при 60 Гц один кадр — 16,7 мс) плюс собственная задержка матрицы монитора или телефона.
  - *Устройство ввода.* У клавиатуры, мыши и сенсорного экрана есть своя задержка опроса. Беспроводные устройства и сенсоры телефонов обычно медленнее проводной клавиатуры.
  - *Браузер и система.* Загрузка процессора, энергосбережение и фоновые вкладки могут добавить несколько миллисекунд.
- **Следствие.** Абсолютные значения на разных устройствах несравнимы, а на одном устройстве систематическая задержка примерно постоянна. Поэтому:
  - в анализе по умолчанию учитываются только сеансы с основного устройства;
  - сравниваются сеансы одного человека между собой, а не с нормами;
  - сохраняется оценка длительности кадра экрана (`frameMs`, медиана интервалов между кадрами во время сигнала) и параметры экрана — для самопроверки.

### 7.5. Прерывание
Если во время теста вкладка свёрнута или скрыта (`visibilitychange`), пользователь ушёл со страницы или нажал «Прервать тест», сеанс сохраняется со статусом «прерван» и в анализ не входит.

Сеанс записывается в базу в момент начала со статусом «идёт». Если страницу закрыли посреди теста, при следующем открытии раздела такой сеанс помечается как прерванный («страница закрыта»).

Экран прохождения теста имеет **один фиксированный вид в обеих темах сайта** (тёмный фон, серая рамка, яркий жёлтый стимул), без украшений, анимаций и талисмана, чтобы тема не влияла на время реакции. Тема сайта в момент теста (выбор пользователя и фактически показанная) всё равно записывается в данные сеанса (`theme`) и в CSV — чтобы при анализе это можно было проверить.

Выход из полноэкранного режима (клавиша Esc) тест не прерывает. Полноэкранный режим запрашивается в момент нажатия «Начать тест». Если браузер его не поддерживает (например, iPhone), тест идёт в окне на всю страницу.

### 7.6. Вопросы после теста
- «Насколько бодрым(ой) вы себя чувствуете?» (0–100), «Насколько вы старались?» (0–100), «Были отвлечения: да/нет».
- **Зачем.** Результат PVT зависит не только от бдительности, но и от мотивации и старания; при недосыпе субъективное старание и мотивация меняются (Mathew et al., 2021). Эти ответы помогают понять, почему отдельный сеанс выбивается.
- Шкалы 0–100 — простые шкалы самооценки этого проекта, а не валидированные инструменты. Ответы необязательны.

### 7.7. Эффект практики: тренировочные сеансы
- При повторном прохождении тестов на скорость результаты улучшаются просто от практики, особенно в первые разы (Scharfen, Blum, Holling, 2018). Чтобы это улучшение не принять за влияние сна или другого фактора, **первые 3 завершённых сеанса** (`PVT.practiceSessions`) помечаются как тренировочные. Они не входят в анализ и выделяются на графиках.
- Считаются только завершённые сеансы с любого устройства; прерванные не считаются.
- Пометка ставится в момент завершения сеанса и потом не меняется.
- Число 3 — проектное решение. Метаанализ показывает, что эффект повторения наиболее выражен в первые повторения, но точное число «достаточных» тренировок он не задаёт.

### 7.8. Устройство
- Перед тестом сайт угадывает тип устройства по user agent; пользователь видит догадку и может её исправить. Сохраняются тип (телефон / планшет / компьютер), user agent и параметры экрана.
- Если тип отличается от основного устройства, перед тестом появляется предупреждение. В анализе по умолчанию учитываются только сеансы, тип устройства которых совпадает с **текущим** основным: если основное устройство сменить в настройках, учитываться начнут сеансы с нового.
- Время суток: перед тестом показывается обычное время прохождения (медиана времени начала прошлых завершённых сеансов) с советом проходить тест примерно в одно время. Внимание меняется в течение суток, поэтому время прохождения — источник разброса.

### 7.9. Самопроверка теста
Раздел для автора (`#/pvt-selfcheck`): гистограмма всех времён реакции (столбики по 25 мс), медианы по устройствам и длительность кадра. Пояснение: у бодрого человека медиана обычно около 200–300 мс; если значения стабильно намного выше, возможна техническая задержка. **TODO: сверить** этот диапазон с Basner et al. ## 8. Карта состояния (графики)

- **Одно значение на день.** Для дневника — значение из записи дня. Для теста — первый учитываемый сеанс дня (завершён, не тренировочный, с основного устройства). Для пульса и давления — первое измерение дня, для PSS-10 — первый результат дня. Так графики используют те же правила, что и проверка гипотез (раздел 9.1).
- **Исключённые сеансы теста** (тренировочные, незавершённые, с другого устройства, повторные за день) по умолчанию показываются серыми пустыми ромбами и подписаны в подсказке и таблице. Переключателем их можно скрыть. В число точек они не входят.
- **Периоды:** неделя (7 дней, включая сегодня), месяц (30 дней), всё время (с первой записи). День считается с учётом границы суток.
- **Число точек.** Под каждым графиком указано число точек за период. Если их меньше **7** (`ANALYSIS.minPointsForConclusions`), выводится предупреждение «данных пока мало для выводов». Порог 7 — проектное решение, он совпадает с минимумом дней в группе гипотезы по умолчанию.
- **Нейтральность.** Подписи описывают показатель, но не оценивают его. Нет цветовой разметки «хорошо/плохо», норм и сравнения с другими людьми.
- **Сравнение двух показателей:**
  - *на одном графике*, у каждого показателя своя ось (так требует ТЗ проекта). У графиков с двумя осями есть известный недостаток: высота и наклон линий зависят от выбранных шкал, и кажущееся «совпадение» может быть случайным. Поэтому под графиком написано, что сравнивать надо совпадение подъёмов и спадов по дням, а не высоту линий;
  - *диаграмма рассеяния* «A против B» — по точке на день, когда есть оба показателя.
  - Рядом всегда стоит предупреждение режима «Исследую»: при переборе многих показателей случайные «связи» находятся обязательно (проблема множественных сравнений). Найденное здесь — идея для гипотезы, а не вывод.
- **Доступность.** Цвета линий проверены на различимость при разных видах дальтонизма в обеих темах. Второй показатель дополнительно отличается пунктиром и квадратными точками, исключённые сеансы — формой (ромб). Под каждым графиком есть таблица с теми же данными.

## 9. Проверка гипотез

Раздел построен по модели персональной науки (Wolf, De Groot, 2020): вопрос → план → фиксация → наблюдение → рассуждение и открытие. Два режима визуально разделены (вкладки, цветная полоса слева):
- **«Исследую»** — свободный просмотр графиков и сравнение любых показателей (раздел 8). Там всегда стоит предупреждение о множественных сравнениях. Найденное там — идея, а не вывод.
- **«Проверяю»** — заранее зафиксированные гипотезы; правила ниже.

### 9.1. Один показатель в день
Сравниваются дни, а не отдельные измерения.
- Если за день несколько сеансов теста, берётся **первый засчитанный** сеанс: завершён, не тренировочный, с основного устройства. В гипотезах сеансы с других устройств не учитываются никогда.
- Если несколько измерений пульса или давления, берётся **первое** за день. Для PSS-10 — первый результат дня.

Так проще объяснить анализ, и это согласуется с советом проходить тест в одно и то же время суток.

### 9.2. План: как дни делятся на группы
- **Фактор** — любое поле дневника, свой фактор, причина стресса, показатель теста, пульс, давление или балл PSS-10.
  - *Числовой фактор* делится порогом. Пользователь выбирает, какая сторона — «условие» (группа A): «меньше порога» или «не меньше порога». Остальные дни — группа B. В подсказке показывается медиана прошлых значений фактора: порог около медианы делит дни примерно поровну. Значения результата при этом не показываются.
  - *Фактор «да/нет»* (свой фактор или причина стресса): A — «да», B — «нет». Причина стресса считается «да», если отмечена в записи дня, и «нет» — во всех остальных записях дня.
- **Результат** — любой числовой показатель (не «да/нет»).
- **Ожидаемое направление:** в группе A результат выше или ниже, чем в B.
- **Сдвиг во времени:** 0 — фактор и результат одного дня (например, сон прошлой ночи, записанный в сегодняшнем дневнике, и тест сегодня); 1 — результат на следующий день после дня фактора.
- **Минимум дней в каждой группе** — по умолчанию 7, допустимо 5–60.

### 9.3. Фиксация и защита от «подглядывания»
- После фиксации параметры гипотезы менять нельзя, можно только создать новую (в том числе «на основе этой»: план копируется в новый черновик). Это идея предрегистрации: решение о способе анализа принимается до того, как увидены данные (Nosek et al., 2018).
- В анализ попадают только дни **после дня фиксации**: день фактора должен быть позже дня фиксации. День фиксации тоже исключается, потому что его данные человек мог уже видеть. При сдвиге 1 день результата всегда позже дня фактора.
- **Итог считается один раз.**
  - **Точка проверки** — первый день результата, к концу которого в **обеих** группах набралось минимальное число дней. Итог считается по всем наблюдениям до этого дня включительно. Поэтому он не зависит от того, когда пользователь открыл страницу.
  - До точки проверки показывается только прогресс («собрано 5 из 7 дней»), без промежуточных медиан и долей.
  - Итог сохраняется вместе со **снимком данных**, по которым он посчитан. Если потом отредактировать записи дневника, итог не изменится.
  - **Почему.** Если смотреть на результат после каждого нового дня и остановиться, когда «получилось», случайная разница рано или поздно покажется настоящей. Каждый взгляд — ещё один шанс увидеть случайное совпадение. Заранее заданный момент проверки этот шанс убирает.
- Данные, собранные после итога, показываются отдельно с пометкой «после завершения проверки — в итог не входят».

### 9.4. Перестановочный тест
- Статистика — **разница медиан** групп (A минус B).
- Вопрос теста: «как часто разница такого размера (или больше) в ожидаемую сторону получалась бы случайно, если бы связи не было». Для этого метки групп 5000 раз (`ANALYSIS.permutations`) случайно перемешиваются, и каждый раз считается разница медиан.
- Тест **односторонний**, в направлении, записанном при фиксации. Для правила «не согласуются» отдельно считается доля для обратного направления.
- **Поправка +1:** p = (число перестановок с разницей не меньше наблюдаемой + 1) / (число перестановок + 1). Настоящее разбиение тоже одна из возможных перестановок, поэтому p никогда не бывает ровно 0. Это стандартная рекомендация (Phipson, Smyth, 2010).
- **Воспроизводимость.** Случайные числа берутся из генератора с зерном, зерно — из ID гипотезы. Повторный расчёт на тех же данных даёт тот же результат.
- **Ограничение медианы.** Если значения в группах повторяются (шкалы 0–10, «да/нет»), медиана меняется скачками, и тест получается осторожным: он чаще отвечает «пока неясно». В крайнем случае, когда в группах всего два разных значения (все дни A = 3, все дни B = 7), почти любое перемешивание даёт ту же разницу, и итог будет «пока неясно» даже при полном разделении групп. Это проверено юнит-тестом. Выбор медианы — осторожный: он защищает от влияния единичных выбросов, но требует больше дней.

### 9.5. Правило итога
Обозначим p — долю перестановок, в которых разница была не меньше наблюдаемой.
- **«Данные согласуются с гипотезой»**: разница в ожидаемую сторону и p ≤ 0,05 (односторонний тест в ожидаемом направлении).
- **«Данные не согласуются с гипотезой»**: разница в обратную сторону и p ≤ 0,05 для теста в обратном направлении.
- **«Пока неясно»**: все остальные случаи, включая нулевую разницу.

Рядом с итогом показываются медианы групп, межквартильный размах, точечная диаграмма обеих групп и понятная доля: «такая разница получалась бы случайно примерно в N случаях из 100».

Граница 0,05 — это общепринятая **условная договорённость**, а не закон природы. Она означает: «такое случайно бывает примерно в 1 случае из 20 или реже». Слово «доказано» нигде не используется.

### 9.6. «Что ещё могло повлиять» (обязательный блок)
Показывается при любом итоге:
- другие обстоятельства этих дней;
- совпадение — не причина (третья переменная, обратная связь);
- регрессия к среднему (Barnett et al., 2005);
- мало данных;
- субъективность самоотчёта и ожидания.

Если результат — показатель теста, добавляется эффект практики (Scharfen et al., 2018), старание и время суток.

### 9.7. Самоэксперимент с чередованием
- Пользователь задаёт условия A и B, показатель (того же дня), ожидаемое направление и длительность (10–60 дней, по умолчанию 14). Начать можно сегодня или завтра.
- **Расписание:** поровну дней A и B (при нечётном числе один лишний день достаётся случайно), порядок случайный. Зерно — из ID эксперимента. Кнопки «перемешать заново» нет, чтобы не выбирать «удобное» расписание. После начала расписание не меняется.
- **Зачем случайность.** Когда условие выбирает жребий, а не человек, на выбор не влияют настроение и обстоятельства дня. Поэтому сравнение ближе к причинному выводу, чем простое наблюдение. Ограничения (ожидания, мало дней) показаны рядом.
- Каждый день сайт напоминает условие (на главной и на странице эксперимента). Пользователь может отметить, выполнено ли условие.
- **Анализ по расписанию:** дни сравниваются по назначенному условию, даже если оно не было выполнено. Так сохраняется главное достоинство жребия. Число таких дней показывается рядом с итогом: если их много, разница может оказаться меньше настоящей.
- До конца эксперимента показывается только, есть ли за день данные, без значений и промежуточных результатов. Итог считается один раз после последнего дня тем же перестановочным тестом и по тому же правилу (9.4–9.5). Нужно хотя бы 3 дня с данными в каждой группе (`MIN_PER_GROUP`), иначе итог — «данных недостаточно».

## 10. Пульс и давление

- **Только запись, без оценки.** Сайт не сравнивает значения с нормами, не пишет «норма», «повышено» или «понижено» и не делает по физиологии выводов о стрессе или здоровье.
- **Ручной ввод:** пульс (уд/мин), давление верхнее и нижнее. Все поля необязательны, но давление вводится парой. За день можно сделать несколько измерений; для графиков и гипотез берётся первое за день (раздел 9.1).
- **Инструкция перед вводом.** Краткие условия из ТЗ проекта: сидя, после 5 минут покоя, не сразу после еды, кофе или нагрузки; для давления — подходящий тонометр и правильное положение манжеты. Подробную инструкцию автор вставляет из официального источника (**TODO**, `src/data/physio.js`).
- **Контекст измерения:** поза, был ли отдых 5 минут, кофеин за 2 часа, нагрузка за час. Время суток (утро 4–12, день 12–18, вечер 18–24, ночь 0–4) вычисляется по времени измерения. Контекст нужен, чтобы при анализе можно было понять, в одинаковых ли условиях сделаны измерения.
- **Проверка правдоподобия** ловит только опечатки, это не нормы:
  - пульс 30–220;
  - верхнее давление 60–260, нижнее 30–160;
  - только целые числа;
  - верхнее больше нижнего.

  Сообщения нейтральные: «похоже на опечатку». Границы — в `src/config.js` (`PHYSIO_INPUT_LIMITS`).
- **ВСР (вариабельность сердечного ритма)** не реализована: для неё нужны данные с датчика, а не ручной ввод. Она упомянута в разделе «Планы развития» в README.

## 11. PSS-10 (Шкала воспринимаемого стресса)

- **Источник шкалы:** Cohen, Kamarck, Mermelstein (1983). Русские версии: Абабков и др. (2016) для взрослых; адаптация для подростков 13–17 лет (Scientific Reports, 2024).
- **Тексты** инструкции, 10 вопросов и промежуточных вариантов ответа **не придуманы**. В `src/data/pss10.js` стоят заглушки, которые автор заполняет дословно из **одной** выбранной версии. Пока заглушки не заполнены, на странице есть предупреждение для автора.
- **Шкала ответов:** по умолчанию 1–5 («никогда» … «очень часто»), как в подростковой адаптации. Вариант 0–4 (оригинал Коэна) включается в `src/config.js` (`PSS.scale`). В одном проекте используется только один вариант. Результаты с разными шкалами не сравниваются между собой.
- **Подсчёт** (`src/logic/pss.js`, покрыт юнит-тестами):
  - пункты 4, 5, 7, 8 — обратные: для шкалы 1–5 1↔5, 2↔4, 3=3; для 0–4 0↔4, 1↔3, 2=2;
  - подшкала «беспомощность» — сумма пунктов 1, 2, 3, 6, 9, 10;
  - подшкала «самоэффективность» — сумма пунктов 4, 5, 7, 8 после переворота;
  - общий балл — сумма всех 10 пунктов после переворота. Диапазоны для 1–5: 10–50, 6–30, 4–20; для 0–4: 0–40, 0–24, 0–16.
  - **TODO: сверить** номера обратных пунктов и состав подшкал с выбранной русской версией.
- **Возраст.** Опросник доступен только тем, кто ответил «13 лет и старше». Младшим показывается сообщение; остальной сайт им доступен.
- **Частота:** не чаще раза в 28 дней (`PSS.minDaysBetween`), потому что вопросы относятся к последнему месяцу. Демо-результаты эту проверку не блокируют. В пилоте опросник проходят в анкетах «до» и «после» (этап 9).
- **Показ результата:** общий балл и подшкалы с диапазоном, изменение по сравнению с прошлым результатом той же шкалы словами («на 4 балла меньше»). **Порогов «норма/стресс» нет**, нет оценок «лучше/хуже», нет сравнения с другими людьми. Есть пояснение, что шкала — не диагноз. Все ответы на 10 вопросов обязательны.
- В CSV сохраняются сырые ответы по пунктам (обратные помечены), баллы и повод заполнения (обычный, пилот «до», пилот «после»).

## 12. Саморегуляция и раздел «Как это устроено»

- **Дыхательное упражнение.** Анимированный круг растёт на вдохе и уменьшается на выдохе, рядом подписи «Вдох/Выдох», секунды до смены фазы и полоска прогресса.
  - Темп по умолчанию — из ТЗ проекта: вдох 4 с, выдох 6 с (медленное дыхание). Настраивается в пределах 2–10 с на фазу.
  - Длительность 1–5 минут, по умолчанию 2. Упражнение заканчивается после последнего целого цикла, поэтому реальная длительность может быть немного меньше выбранной.
  - **Без обещаний:** сайт не утверждает, что упражнение «снижает стресс». Вместо этого — кнопка «Проверить, помогает ли это мне». Она открывает самоэксперимент с уже заполненными условиями A («дыхательное упражнение…») и B («без упражнения»).
  - Добавлено общее предостережение: «Если неприятно или кружится голова — остановитесь». **TODO: сверить** с источником или убрать.
  - Если в системе включено «уменьшить движение» (`prefers-reduced-motion`), круг не меняет размер; остаются подписи и полоска.
- **Советы** по перерывам, сну и учебному/рабочему пространству — заглушки (`src/data/tips.js`). Под каждым советом есть поле для источника и ссылки. Ссылки открываются только по нажатию, автоматических запросов нет.
- Рядом всегда стоит пояснение: «то, что помогает одним, может не помогать другим — проверьте на себе».
- **«Как это устроено»** — пять коротких страниц с готовой структурой и заглушками (`src/data/learn.js`):
  1. почему нельзя судить о стрессе по одному показателю;
  2. что измеряет PVT и чем бдительность отличается от стресса;
  3. что такое PSS-10 и почему это не диагноз;
  4. совпадение и причина, регрессия к среднему, эффект практики;
  5. ограничения сайта.

  У каждого раздела — подсказка, о чём писать и по какому источнику.

## 13. Режим пилотного исследования

- **Включение** — в настройках. Нужен код участника вместо имени: по умолчанию сайт предлагает случайный код вида «P042», но исследователь может выдать свой. Допустимы только латинские буквы и цифры, 2–12 символов, чтобы туда не попало имя. Число дней до анкеты «после» по умолчанию 14 (от 3 до 90).
- **Демо-данные и пилот.** Режим пилота нельзя включить, пока в базе есть демо-данные; рядом предлагается их удалить. Демо-данные никогда не попадают в выгрузку для исследователя и в сводку.
- **Анкета «до»:**
  - вопрос «Можете ли вы назвать факторы, которые влияют на вашу концентрацию? Какие?» (текст из ТЗ);
  - PSS-10, если участнику 13 лет и больше.
- **Анкета «после»** — через заданное число дней, в двух частях:
  1. тот же вопрос о факторах и PSS-10;
  2. опросник удобства SUS и открытые вопросы обратной связи.

  PSS-10 в анкетах пилота не подчиняется правилу «раз в 28 дней»: у таких результатов своя пометка повода. Вопросы обратной связи — рабочий вариант разработчика, автор может их изменить (`src/data/pilotTexts.js`).
- **SUS:** 10 пунктов, шкала 1–5. Тексты пунктов и подписи шкалы — заглушки для валидированного русского перевода (`src/data/sus.js`). Подсчёт стандартный (из ТЗ): нечётные пункты — ответ минус 1, чётные — 5 минус ответ, сумма × 2,5 = балл 0–100. Покрыт юнит-тестами.
- **Сводка участия:**
  - число дней с записями в дневнике;
  - число завершённых сеансов теста;
  - число созданных и завершённых гипотез;
  - число самоэкспериментов.

  Всё без демо-данных.
- **Выгрузка для исследователя** — файл с кодом участника в названии (`pilot-P042-ГГГГ-ММ-ДД`):
  - **JSON** — все данные пилота: анкеты, сводка, записи;
  - **CSV** — одна строка на участника: сводка, ответы анкет, баллы PSS-10 «до/после», SUS по пунктам и общий, отзывы. Строки всех участников удобно собрать в одну таблицу.
- **Что убрано из выгрузки как возможные личные данные:**
  - заметки дневника и поле «своя причина» (остаётся только пометка «заполнено»);
  - тексты вопросов и выводов по гипотезам (тоже только «заполнено»);
  - user agent браузера (остаётся тип устройства);
  - названия своих факторов (заменены на «фактор 1», «фактор 2»…);
  - снимки дней внутри итогов гипотез (сами дни есть в таблицах записей).

  Ответы на открытые вопросы анкет пилота и формулировки условий самоэксперимента **остаются**: ради первых и делается выгрузка, а вторые обычно описывают действие («перерыв 10 минут»). **Решение стоит согласовать с руководителем проекта.**

## 14. Демо-данные

- Кнопка в настройках добавляет **выдуманные** данные за 30 дней: дневник, сеансы теста с попытками (первые 3 тренировочные, один незавершённый), измерения пульса и давления, два результата PSS-10, две гипотезы (одна получает итог сразу, вторая ещё собирает данные), завершённый самоэксперимент и демо-фактор «кофе (демо)».
- Связи в демо-данных заложены специально (меньше сна — выше стресс и медленнее реакция; в дни A самоэксперимента реакция немного быстрее), чтобы на защите было что показать. Это пример работы сайта, а **не** научный факт и не данные реального человека.
- Генерация воспроизводима: зерно случайных чисел фиксировано. Дни с короткими и обычными часами сна распределены поровну, чтобы обе группы демо-гипотезы набрали нужное число дней.
- Каждая запись помечена `demo: true`. На всех страницах видна полоска «есть демо-данные».
- Удаление одной кнопкой: стираются только записи с пометкой и демо-фактор.
- Дни, за которые уже есть настоящая запись дневника, пропускаются.
- Демо-данные не мешают правилу «PSS-10 раз в 28 дней», не попадают в выгрузку для исследователя и в сводку пилота. Пока они есть, пилот включить нельзя.

- У каждого поля есть подпись. Группы вариантов оформлены как `fieldset` с `legend`. На каждой странице один заголовок `h1`, уровни заголовков не пропускаются, повторяющихся id нет; проверено автоматическим скриптом на 19 страницах.
- Контраст текста к фону — не ниже 7:1 в обеих темах. Рамка фокуса заметная, её контраст к фону не ниже 3:1. Цвета линий графиков проверены на различимость при дальтонизме; второй показатель отличается ещё и пунктиром, исключённые сеансы — формой.
- Управление с клавиатуры: ссылка «Перейти к содержимому», видимый фокус, ползунки работают стрелками, тест — пробелом. После перехода между страницами фокус переводится на заголовок.
- Под каждым графиком есть таблица с теми же данными. При настройке «уменьшить движение» дыхательный круг не анимируется.
- Язык страницы — русский (`lang="ru"`).
