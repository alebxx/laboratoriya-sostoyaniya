# Методика: решения и их обоснование

Здесь записаны все методические решения проекта: что сделано, почему и на какой источник это опирается. Числовые параметры живут в `src/config.js`; если меняете параметр там, обновите и этот файл.

## 1. Общие принципы

- **Не медицинский инструмент.** Сайт не ставит диагнозов, не выводит «уровень стресса» из физиологии или теста, не сравнивает значения с нормами и не сравнивает пользователя с другими людьми. Все сравнения делаются только внутри данных одного человека.
- **Связь — не причина.** Все выводы формулируются как совпадения: «в дни, когда…, вы чаще…». Причинные формулировки не используются.
- **Приватность.** Данные хранятся только в браузере пользователя (IndexedDB). Сервера, регистрации, аналитики и внешних запросов нет. Шрифты системные, библиотеки входят в сборку.

## 2. Хранение данных

- **Где:** IndexedDB, база `laboratoriya-sostoyaniya`. localStorage используется только для выбранной темы оформления.
- **Версии:** у базы есть номер версии (`DB_VERSION` в `src/db/db.js`), у файла экспорта — номер формата (`SCHEMA_VERSION` в `src/config.js`). При изменении структуры номер увеличивается, а старые данные переводятся в новый формат функциями-миграциями.
- **Одна запись дневника на день:** ключ записи — дата, поэтому повторное сохранение заменяет запись за этот день (её можно редактировать).
- **Риск потери данных.** Данные браузера пропадают в режиме инкогнито и при очистке данных сайтов. Поэтому:
  - на первом экране есть предупреждение;
  - сайт просит браузер хранить данные постоянно (`navigator.storage.persist()`), но браузер может отказать;
  - раз в 7 дней (если есть данные) появляется напоминание сделать резервную копию, его можно отложить на 1 день.

## 3. Граница суток

Записи и сеансы, сделанные до **4:00**, относятся к предыдущему дню (`DAY_START_HOUR` в `src/config.js`).

**Зачем.** Если человек заполняет дневник или проходит тест в 01:00 ночи, по смыслу это ещё «вчерашний» день: он ещё не спал. Без этой границы поздние записи попадали бы в следующий день, и связь «сон прошлой ночью → состояние сегодня» перепутывалась бы.

Это проектное решение, а не научная норма. Порог можно поменять.

## 4. Экспорт и импорт

- **JSON** — полная копия всех хранилищ с полями `app`, `schemaVersion`, `exportedAt`. Из неё можно всё восстановить.
- **CSV** — отдельная таблица для каждого раздела (дневник, физиология, сеансы теста, попытки теста, PSS-10, гипотезы). Разделитель столбцов — точка с запятой, дробная часть чисел — через запятую («6,5»), в начале файла стоит BOM (знак кодировки), чтобы русская версия Excel правильно открыла файл. Списки внутри ячейки записываются как JSON-текст.
- **Импорт** принимает только JSON этого сайта. Файл проверяется (название приложения, версия формата, известные разделы). Файл от более новой версии сайта не принимается. Импорт **заменяет** текущие данные одной транзакцией: при ошибке данные не меняются.

## 5. Дневник

- **Одна запись на день**, её можно редактировать. День записи считается с учётом границы суток (раздел 3). Можно выбрать и прошедший день, если запись была забыта, но не будущий.
- **Время записи.** Сохраняются время создания (`createdAt`) и время последнего изменения (`updatedAt`).
- **Все поля необязательны.** Не отмеченное поле сохраняется как пустое (`null`), а не как 0: «не ответил» и «ответил 0» — разные вещи. Поэтому у ползунка есть состояние «не отмечено». Пока ползунок не сдвинули, значение не сохраняется, а кнопка «Сбросить» возвращает это состояние. Совсем пустая запись не сохраняется.
- **Шкалы 0–10** для стресса, усталости, качества сна и концентрации — это простые шкалы самооценки, сделанные для этого проекта. Это **не** валидированные опросники, и их значения нельзя сравнивать с чужими. Они нужны только для сравнения дней одного человека между собой. Подписи краёв шкал нейтральные.
- **Сон** — часы от 0 до 16 с шагом 0,5 («прошлой ночью», то есть относится к дню записи).
- **Настроение** — 5 вариантов (1–5).
- **Свои факторы** — пользователь сам создаёт отметки «да/нет» или числа. Фактор нельзя удалить, только скрыть: так не теряются старые отметки и не ломаются гипотезы, которые на него опираются. Для «да/нет» есть третий вариант «не отмечено», чтобы отсутствие отметки не считалось ответом «нет».
- **CSV дневника:** заголовки столбцов на русском, со шкалой в скобках («Стресс (0–10)»). Время указано по местному времени в виде «ГГГГ-ММ-ДД ЧЧ:ММ». Причины записаны через запятую, каждый свой фактор — отдельный столбец «Фактор: название», демо-записи помечены. В JSON-копии названия полей остаются английскими: их читает программа при импорте.

## 6. Мягкая забота

- Если стресс от **9** и выше отмечен **3 дня подряд** (настройка `CARE` в `src/config.js`), после сохранения записи показывается спокойное сообщение. В нём говорится, что сайт не заменяет поддержку, и названо, к кому можно обратиться. Текст вставляет автор (`src/data/messages.js`).
- «Подряд» — значит по календарным дням без пропусков. День без записи или без отметки стресса прерывает серию.
- Сообщение показывается **один раз на серию**. Если высокий стресс продолжается, оно не повторяется. Если серия прервалась, а потом началась новая, сообщение покажется снова.
- Это не оценка состояния и не диагноз: сайт не делает выводов о человеке, а только напоминает о поддержке. Пороги — проектное решение, а не клинический критерий.

## 7. Тест на внимание PVT-B

### 7.1. Что измеряет тест
PVT (Psychomotor Vigilance Test) — тест на простое время реакции: человек как можно быстрее реагирует на сигнал, который появляется в случайные моменты. Он измеряет **бдительность** (устойчивость внимания) и чувствителен к недосыпу (Lim, Dinges, 2010). PVT **не измеряет стресс**, поэтому сайт не делает по нему выводов о стрессе.

PVT-B — укороченный трёхминутный вариант, предложенный и проверенный Basner, Mollicone, Dinges (2011).

### 7.3. Показатели сеанса
- **Медиана времени реакции** — главный показатель. Считается по всем ответам на сигнал, кроме фальстартов; пропуски входят. Медиана устойчива к единичным очень долгим реакциям.
- **Скорость реакции** — среднее значение 1/RT (в 1/с, то есть 1000 / RT в мс). Его часто используют как основной показатель PVT (**TODO: сверить** с Basner et al., 2011, какие показатели там названы наиболее чувствительными). В отличие от медианы, он учитывает и медленные реакции.
- **Пропуски** — число реакций ≥ 355 мс (включая «нет ответа»).
- **Фальстарты** — нажатия до сигнала и реакции < 100 мс.
- **Стимулы** — сколько раз появлялся сигнал. Нажатия до сигнала стимулами не считаются, а реакции < 100 мс — считаются: сигнал был.
- Сырые данные каждой попытки сохраняются: интервал ожидания, момент сигнала и нажатия от начала теста, время реакции, тип попытки, чем нажато.

### 7.4. Измерение времени в браузере и какие задержки остаются
- **Часы.** Используется `performance.now()` — монотонные часы браузера с точностью до долей миллисекунды. Они не зависят от перевода системного времени.
- **Появление сигнала.** Таймер (`setTimeout`) срабатывает примерно через нужный интервал, после чего сигнал рисуется в ближайшем кадре: внутри колбэка `requestAnimationFrame`. Сразу после изменения страницы запоминается момент сигнала. Так момент привязан к кадру отрисовки, а не к произвольному моменту таймера.
- **Момент нажатия.** Берётся `event.timeStamp` — время самого события клавиатуры или касания по тем же часам. Оно точнее, чем время, когда обработчик дошёл до события.
- **Что остаётся неточным:**
  - *Экран.* Между командой «нарисовать» и реальным появлением картинки проходит от долей кадра до 1–2 кадров (при 60 Гц один кадр — 16,7 мс) плюс собственная задержка матрицы монитора или телефона.
  - *Устройство ввода.* У клавиатуры, мыши и сенсорного экрана есть своя задержка опроса. Беспроводные устройства и сенсоры телефонов обычно медленнее проводной клавиатуры.
  - *Браузер и система.* Загрузка процессора, энергосбережение и фоновые вкладки могут добавить несколько миллисекунд.
- **Следствие.** Абсолютные значения на разных устройствах несравнимы, а на одном устройстве систематическая задержка примерно постоянна. Поэтому:
  - в анализе по умолчанию учитываются только сеансы с основного устройства;
  - сравниваются сеансы одного человека между собой, а не с нормами;
  - сохраняется оценка длительности кадра экрана (`frameMs`, медиана интервалов между кадрами во время сигнала) и параметры экрана — для самопроверки.

### 7.5. Прерывание
Если во время теста вкладка свёрнута или скрыта (`visibilitychange`), пользователь ушёл со страницы или нажал «Прервать тест», сеанс сохраняется со статусом «прерван» и в анализ не входит.

Сеанс записывается в базу в момент начала со статусом «идёт». Если страницу закрыли посреди теста, при следующем открытии раздела такой сеанс помечается как прерванный («страница закрыта»).

Выход из полноэкранного режима (клавиша Esc) тест не прерывает. Полноэкранный режим запрашивается в момент нажатия «Начать тест». Если браузер его не поддерживает (например, iPhone), тест идёт в окне на всю страницу.

### 7.6. Вопросы после теста
- «Насколько бодрым(ой) вы себя чувствуете?» (0–100), «Насколько вы старались?» (0–100), «Были отвлечения: да/нет».
- **Зачем.** Результат PVT зависит не только от бдительности, но и от мотивации и старания; при недосыпе субъективное старание и мотивация меняются (Mathew et al., 2021). Эти ответы помогают понять, почему отдельный сеанс выбивается.
- Шкалы 0–100 — простые шкалы самооценки этого проекта, а не валидированные инструменты. Ответы необязательны.

### 7.7. Эффект практики: тренировочные сеансы
- При повторном прохождении тестов на скорость результаты улучшаются просто от практики, особенно в первые разы (Scharfen, Blum, Holling, 2018). Чтобы это улучшение не принять за влияние сна или другого фактора, **первые 3 завершённых сеанса** (`PVT.practiceSessions`) помечаются как тренировочные. Они не входят в анализ и выделяются на графиках.
- Считаются только завершённые сеансы с любого устройства; прерванные не считаются.
- Пометка ставится в момент завершения сеанса и потом не меняется.
- Число 3 — проектное решение. Метаанализ показывает, что эффект повторения наиболее выражен в первые повторения, но точное число «достаточных» тренировок он не задаёт.

### 7.8. Устройство
- Перед тестом сайт угадывает тип устройства по user agent; пользователь видит догадку и может её исправить. Сохраняются тип (телефон / планшет / компьютер), user agent и параметры экрана.
- Если тип отличается от основного устройства, перед тестом появляется предупреждение. В анализе по умолчанию учитываются только сеансы, тип устройства которых совпадает с **текущим** основным: если основное устройство сменить в настройках, учитываться начнут сеансы с нового.
- Время суток: перед тестом показывается обычное время прохождения (медиана времени начала прошлых завершённых сеансов) с советом проходить тест примерно в одно время. Внимание меняется в течение суток, поэтому время прохождения — источник разброса.

### 7.9. Самопроверка теста
Раздел для автора (`#/pvt-selfcheck`): гистограмма всех времён реакции (столбики по 25 мс), медианы по устройствам и длительность кадра. Пояснение: у бодрого человека медиана обычно около 200–300 мс; если значения стабильно намного выше, возможна техническая задержка. **TODO: сверить** этот диапазон с Basner et al. ## 8. Карта состояния (графики)

- **Одно значение на день.** Для дневника — значение из записи дня. Для теста — первый учитываемый сеанс дня (завершён, не тренировочный, с основного устройства). Для пульса и давления — первое измерение дня, для PSS-10 — первый результат дня. Так графики используют те же правила, что и проверка гипотез (раздел 9.1).
- **Исключённые сеансы теста** (тренировочные, незавершённые, с другого устройства, повторные за день) по умолчанию показываются серыми пустыми ромбами и подписаны в подсказке и таблице. Переключателем их можно скрыть. В число точек они не входят.
- **Периоды:** неделя (7 дней, включая сегодня), месяц (30 дней), всё время (с первой записи). День считается с учётом границы суток.
- **Число точек.** Под каждым графиком указано число точек за период. Если их меньше **7** (`ANALYSIS.minPointsForConclusions`), выводится предупреждение «данных пока мало для выводов». Порог 7 — проектное решение, он совпадает с минимумом дней в группе гипотезы по умолчанию.
- **Нейтральность.** Подписи описывают показатель, но не оценивают его. Нет цветовой разметки «хорошо/плохо», норм и сравнения с другими людьми.
- **Сравнение двух показателей:**
  - *на одном графике*, у каждого показателя своя ось (так требует ТЗ проекта). У графиков с двумя осями есть известный недостаток: высота и наклон линий зависят от выбранных шкал, и кажущееся «совпадение» может быть случайным. Поэтому под графиком написано, что сравнивать надо совпадение подъёмов и спадов по дням, а не высоту линий;
  - *диаграмма рассеяния* «A против B» — по точке на день, когда есть оба показателя.
  - Рядом всегда стоит предупреждение режима «Исследую»: при переборе многих показателей случайные «связи» находятся обязательно (проблема множественных сравнений). Найденное здесь — идея для гипотезы, а не вывод.
- **Доступность.** Цвета линий проверены на различимость при разных видах дальтонизма в обеих темах. Второй показатель дополнительно отличается пунктиром и квадратными точками, исключённые сеансы — формой (ромб). Под каждым графиком есть таблица с теми же данными.

## 9. Проверка гипотез (согласовано, реализуется на этапе 5)

### 9.1. Один показатель в день
Сравниваются дни, а не отдельные измерения.
- Если за день несколько сеансов теста, берётся **первый засчитанный** сеанс: завершён, не тренировочный, с основного устройства.
- Если несколько измерений пульса или давления, берётся **первое** за день.

Так проще объяснить анализ, и это согласуется с советом проходить тест в одно и то же время суток.

### 9.2. Фиксация и защита от «подглядывания»
- После фиксации параметры гипотезы менять нельзя, можно только создать новую. В анализ попадают только данные **после** даты фиксации. Это идея предрегистрации: решение о способе анализа принимается до того, как увидены данные (Nosek et al., 2018).
- **Итог считается один раз**: когда в обеих группах набрано заданное при фиксации минимальное число дней. До этого показывается только прогресс («собрано 5 из 7 дней»), без промежуточных медиан и долей.
  - **Почему.** Если смотреть на результат после каждого нового дня и остановиться, когда «получилось», случайная разница рано или поздно покажется настоящей. Каждый взгляд — ещё один шанс увидеть случайное совпадение. Заранее заданный момент проверки этот шанс убирает.
- Данные, собранные после итога, можно смотреть, но с пометкой «после завершения проверки». Итог при этом не пересчитывается.

### 9.3. Перестановочный тест
- Сравниваются **медианы** двух групп дней.
- Вопрос теста: «как часто разница такого размера (или больше) в ожидаемую сторону получалась бы случайно, если бы связи не было». Для этого метки групп много раз (по умолчанию 5000) случайно перемешиваются, и каждый раз считается разница медиан.
- Тест **односторонний**, в направлении, записанном при фиксации.

### 9.4. Правило итога
Обозначим p — долю перестановок, в которых разница была не меньше наблюдаемой.
- **«Данные согласуются с гипотезой»**: разница в ожидаемую сторону и p ≤ 0,05 (односторонний тест в ожидаемом направлении).
- **«Данные не согласуются с гипотезой»**: разница в обратную сторону и p ≤ 0,05 для теста в обратном направлении.
- **«Пока неясно»**: все остальные случаи.

Рядом с итогом показываются медианы групп и понятная доля: «такая разница получалась случайно в N случаях из 100».

Граница 0,05 — это общепринятая **условная договорённость**, а не закон природы. Она означает: «такое случайно бывает примерно в 1 случае из 20 или реже».
