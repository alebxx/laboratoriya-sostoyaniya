# Лаборатория состояния

Исследовательский проект: сайт, на котором человек ведёт дневник субъективного стресса, записывает пульс и давление, проходит короткий тест на внимание (PVT-B) и сам проверяет гипотезы о связях между этими показателями.

**Это не медицинский инструмент.** Сайт не ставит диагнозов, не определяет «уровень стресса» и не сравнивает показатели с нормами или с другими людьми.

**Приватность.** У сайта нет сервера, регистрации, аналитики и внешних запросов: шрифты системные, библиотеки входят в сборку. Все данные хранятся только в браузере пользователя. Их можно выгрузить (CSV, JSON), загрузить обратно и полностью удалить.

## Что умеет сайт

| Раздел | Что там |
|---|---|
| Первый вход | Что сайт делает и чего не делает, где хранятся данные, вопрос «13 лет и старше?», выбор основного устройства |
| Дневник | Одна запись в день: стресс, усталость, настроение, сон, концентрация, причины стресса, свои факторы, заметка |
| Тест внимания | Трёхминутный тест на время реакции (PVT-B), тренировочные сеансы, учёт устройства, самопроверка |
| Пульс и давление | Ручной ввод с инструкцией и контекстом измерения, без оценки значений |
| Карта состояния | Графики во времени, сравнение двух показателей, рассеяние |
| Гипотезы | «Исследую» (поиск идей) и «Проверяю» (мастер из 5 шагов с фиксацией), самоэксперимент с чередованием |
| PSS-10 | Шкала воспринимаемого стресса (с 13 лет, не чаще раза в месяц, все результаты на графике) |
| Саморегуляция | Дыхательное упражнение, советы со ссылками на источники, связка с самоэкспериментом |
| Как это устроено | Короткие объяснения простым языком |
| Настройки и данные | Тема, устройство, экспорт и импорт, удаление, демо-режим, режим пилота |
| Пилот (если включён) | Код участника, анкеты «до» и «после», SUS, выгрузка для исследователя |

## Как запустить на своём компьютере

Нужен Node.js версии 20 или новее. На этом компьютере он лежит в папке `~/.local/node`. Чтобы терминал его нашёл, в каждом новом окне терминала сначала выполните:

```bash
export PATH="$HOME/.local/node/bin:$PATH"
```

Затем в папке проекта установите зависимости (один раз):

```bash
npm install
```

и запустите сайт:

```bash
npm run dev
```

Откройте адрес, который появится в терминале (обычно http://localhost:5173). Остановить — `Ctrl+C` в терминале.

| Команда | Что делает |
|---|---|
| `npm run dev` | Запускает сайт для разработки: изменения в коде видны сразу |
| `npm test` | Запускает автоматические тесты (расчёты, экспорт, импорт) |
| `npm run build` | Собирает готовый сайт в папку `dist/` |
| `npm run preview` | Показывает собранный сайт локально (так он будет выглядеть после публикации) |

## Демо-режим (для защиты проекта)

«Настройки и данные» → «Демо-режим» → **«Заполнить тестовыми данными за 30 дней»**. Появятся записи дневника, сеансы теста, измерения, два результата PSS-10, две гипотезы (одна уже с итогом, вторая ещё собирает данные) и завершённый самоэксперимент.

- Это **выдуманные** данные. Связи в них заложены специально, чтобы было что показать.
- Каждая запись помечена как демо. Пока демо-данные есть, на всех страницах видна жёлтая полоска.
- Дни, за которые уже есть ваши записи в дневнике, пропускаются: ваши данные не перезаписываются.
- Удаляются одной кнопкой **«Удалить демо-данные»**, ваши записи при этом остаются.
- Во время пилота демо добавлять нельзя, а пилот нельзя включить, пока есть демо-данные.

## Структура папок

```
index.html            — каркас страницы: шапка, меню, место для содержимого
src/
  main.js             — запуск сайта
  router.js           — какая страница показывается по какому адресу
  config.js           — ВСЕ настраиваемые числа (длительность теста, пороги, сроки)
  db/                 — хранение данных в браузере (IndexedDB)
    db.js             — структура базы и миграции
    repo.js           — простые функции «сохранить / прочитать / удалить»
    exportImport.js   — выгрузка и загрузка данных
    analysisData.js   — загрузка данных для анализа, «один итог» гипотез
    demoLoader.js     — загрузка демо-данных
  logic/              — расчёты без интерфейса (их проверяют тесты)
  data/               — тексты (в том числе заглушки для текстов из источников)
  pages/              — страницы сайта, по файлу на страницу
  ui/                 — общие элементы: меню, тема, ползунки, графики
  styles/             — оформление (theme.css — цвета светлой и тёмной темы)
public/               — файлы, которые копируются как есть (иконка, офлайн-режим)
tests/                — автоматические тесты (Vitest)
docs/
  methodology.md      — методические решения и источники
  todo-content.md     — какие тексты нужно вставить из источников
.github/workflows/
  deploy.yml          — автоматическая публикация на GitHub Pages
```

Главная идея: в `logic/` лежат **расчёты** (их проверяют тесты), в `pages/` — то, что **видно на экране**, в `data/` — **тексты**, в `config.js` — **все числа**.

## Как опубликовать на GitHub Pages

Сайт публикуется бесплатно на GitHub Pages и будет доступен по адресу вида `https://ВАШ-ЛОГИН.github.io/НАЗВАНИЕ-РЕПОЗИТОРИЯ/`. Публикацию делает файл `.github/workflows/deploy.yml`: при каждом обновлении кода GitHub сам запускает тесты, собирает сайт и выкладывает его. Если тесты не прошли, сайт не обновится.

**Один раз:**

1. Зарегистрируйтесь на [github.com](https://github.com).
2. Нажмите **New repository**. Придумайте название (например, `laboratoriya-sostoyaniya`), выберите **Public**, файлы README и .gitignore **не** добавляйте, нажмите **Create repository**.
3. GitHub покажет адрес репозитория вида `https://github.com/ВАШ-ЛОГИН/laboratoriya-sostoyaniya.git`. В терминале, в папке проекта, выполните (подставив свой адрес):

   ```bash
   git remote add origin https://github.com/ВАШ-ЛОГИН/laboratoriya-sostoyaniya.git
   ```

   ```bash
   git push -u origin main
   ```

   При первом `git push` GitHub попросит войти. Удобнее всего установить [GitHub Desktop](https://desktop.github.com) или GitHub CLI и войти через них.
4. На странице репозитория откройте **Settings → Pages**. В поле **Source** выберите **GitHub Actions**.
5. Откройте вкладку **Actions**. Там появится запуск «Публикация на GitHub Pages». Когда он станет зелёным (1–2 минуты), сайт доступен по адресу из **Settings → Pages**.

**Каждый раз после изменений:**

```bash
git add -A
```

```bash
git commit -m "Что изменилось"
```

```bash
git push
```

Через пару минут сайт обновится сам.

**Офлайн-режим и обновления.** После первого открытия сайт работает без интернета: файлы сохраняются в кэше браузера (`public/sw.js`). При обновлении сайта браузер подхватит новую версию при следующем открытии. Если после крупного изменения у кого-то остаётся старая версия, увеличьте номер в строке `CACHE_NAME = 'laboratoriya-v1'` в `public/sw.js` (например, на `v2`).

**Без GitHub Actions.** Можно выложить сайт и вручную: `npm run build` создаёт папку `dist/` с готовыми файлами, и её содержимое можно разместить на любом хостинге статических сайтов. Все пути в сборке относительные, поэтому сайт работает в любой папке.

## Тесты

`npm test` запускает больше 230 автоматических проверок. Они проверяют:
- медиану, межквартильный размах и 1/RT;
- классификацию попыток теста;
- исключение тренировочных, незавершённых сеансов и сеансов с другого устройства;
- подсчёт PSS-10 и SUS на примерах, посчитанных вручную;
- разделение дней на группы для гипотез со сдвигом и отбором после фиксации;
- перестановочный тест на данных с известным ответом;
- экспорт, импорт, удаление и демо-данные;
- выгрузку для исследователя без личных данных;
- контраст всех цветов обеих тем, позы талисмана, приветствие и поздравления.

## Планы развития

- **Вариабельность сердечного ритма (ВСР).** Сейчас не реализована: для неё нужны точные интервалы между ударами сердца с датчика (нагрудный пульсометр, часы), а не ручной ввод. Возможное развитие — импорт данных с такого датчика.
